# Red Hat Agents

A shared repository of AI agent assets — skills, agent definitions, prompts, and references — organized by role. Teams contribute reusable agent components that can be installed into any AI-assisted development workflow.

## Getting Started

Before using any agents, run these two setup steps:

### 1. Configure Jira access

Use the **jira-setup** skill to configure Atlassian MCP tools and generate an API token:

```
/jira-setup
```

This walks you through creating an Atlassian API token and configuring your AI tool's MCP settings so all agents can interact with Jira.

### 2. Describe your workflow

Use the **process-interview** skill to teach the agents how your team uses Jira:

```
/process-interview
```

This interviews you about your project's Jira configuration — project key, required fields, statuses, epic conventions, story points, blocking workflows, and more. It produces a `local/jira-workflow.md` file that all agents read to understand your specific setup.

The `local/` directory is gitignored so your personal configuration stays local to your clone.

## Repository Structure

```
Product Owners/
├── agents/          # Agent definitions (persona, tools, behavior)
├── skills/          # Reusable skills invoked by agents or users
├── prompts/         # Prompt templates and system instructions
└── references/      # Reference docs, style guides, domain context
local/               # Your personal config (gitignored)
└── jira-workflow.md # Generated by /process-interview
```

Each role directory follows this same structure. Additional roles can be added by creating a new top-level directory.

## Available Agents

### Product Owners

| Agent | Purpose |
|-------|---------|
| **Process Discoverer** | Interviews you about your Jira workflow and generates local config |
| **Backlog Curator** | Keeps the backlog healthy, prioritized, and grooming-ready |
| **Intake Triager** | Classifies, assesses, and routes incoming work |
| **Delivery Tracker** | Monitors progress, surfaces risks, generates status updates |

## Contributing

1. Pick or create the appropriate role directory (e.g., `Product Owners/`).
2. Add your asset to the correct subdirectory (`agents/`, `skills/`, `prompts/`, or `references/`).
3. Include a short description at the top of each file explaining what it does and when to use it.
4. Submit a merge request for review.

See individual subdirectory `README.md` files for format details and examples.
