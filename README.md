# Red Hat Agents

A shared repository of AI agent assets — skills, agent definitions, prompts, and references — organized by role. Teams contribute reusable agent components that can be installed into any AI-assisted development workflow.

## Getting Started

Before using any agents, run these two setup steps:

### 1. Configure Jira access

Use the **jira-setup** skill to configure Atlassian MCP tools and generate an API token:

```
/jira-setup
```

This walks you through creating an Atlassian API token and configuring your AI tool's MCP settings so all agents can interact with Jira.

### 2. Describe your workflow

Use the **process-interview** skill to teach the agents how your team uses Jira:

```
/process-interview
```

This interviews you about your project's Jira configuration — project key, required fields, statuses, epic conventions, story points, blocking workflows, and more. It produces a `local/jira-workflow.md` file that all agents read to understand your specific setup.

The `local/` directory is gitignored so your personal configuration stays local to your clone.

## Available Agents

### Product Owners

Tactical, backlog-focused agents for day-to-day Jira operations.

| Agent | Purpose | Skills |
|-------|---------|--------|
| **Process Discoverer** | Interviews you about your Jira workflow, generates local config | process-interview |
| **Backlog Curator** | Keeps the backlog healthy, prioritized, and grooming-ready | backlog-health-check, grooming-prep, priority-rebalance |
| **Intake Triager** | Classifies, assesses, and routes incoming work | intake-triage, impact-assessment, acceptance-criteria-writer |
| **Delivery Tracker** | Monitors progress, surfaces risks, generates status updates | epic-health, status-report, dependency-mapper |

### Product Managers

Strategic, outward-facing agents for roadmap, market analysis, and stakeholder communication.

| Agent | Purpose | Skills |
|-------|---------|--------|
| **Roadmap Strategist** | Plans, evaluates, and communicates the product roadmap | roadmap-review, quarter-planning, roadmap-brief |
| **Requirements Analyst** | Translates customer needs into structured specs and epics | feature-spec-writer, customer-signal-aggregator |
| **Market Analyst** | Defines market problems, maps competitors, assesses opportunities | market-problem-definition, competitive-landscape, opportunity-assessment |
| **Stakeholder Communicator** | Produces decision records, release notes, and executive briefs | decision-record, release-notes-drafter, stakeholder-brief |

### Shared Skills

Used by all agents across all roles.

| Skill | Purpose |
|-------|---------|
| **jira-setup** | One-time Atlassian API token + MCP configuration |
| **process-interview** | Interview-driven Jira workflow config generation |
| **suggest-improvement** | File issues/MRs against this repo when agents find gaps or improvements |

## Self-Improvement

All agents include the `suggest-improvement` shared skill. When an agent encounters a gap, error, or improvement opportunity in its own skills or workflows, it files a GitLab issue (and optionally an MR) against this repository. This creates a feedback loop where real-world usage continuously improves the agents.

Issues are always reported to the user before filing — the user can approve or veto.

## Contributing

1. Pick or create the appropriate role directory (e.g., `Product Owners/`, `Product Managers/`).
2. Add your asset to the correct subdirectory (`agents/`, `skills/`, `prompts/`, or `references/`).
3. For skills shared across roles, add them to `shared/skills/`.
4. Include a short description at the top of each file explaining what it does and when to use it.
5. Submit a merge request for review.

See individual subdirectory `README.md` files for format details and examples.
